# توثيق منصة صفحات الروابط

هذا الملف هو المرجع الإلزامي لأي Agent يعمل على منصة صفحات الروابط. الهدف هو أن تتم إضافة الصفحات الجديدة بنفس روح المنتج الحالي، وبنفس التصميم والروابط والمميزات، دون اختراع نظام جديد أو تغيير الهوية من تلقاء نفسه.

## 1. تعريف المنتج

منصة صفحات الروابط هي أطلس عربي بصري يجمع صفحات مواقع متعددة في بطاقات وصفحات تفاصيل قابلة للتصفح. كل صفحة لها:

- عنوان عربي واضح.
- صورة مناسبة.
- تصنيف.
- رابط خارجي أصلي.
- صفحة تفاصيل داخلية.
- مقال عربي طويل مرتبط بعنوان الصفحة.
- كلمات بحث رئيسية مرتبطة Backlinks بالموقع الرئيسي للقسم.
- مسار داخلي عربي مبني من عنوان الصفحة.

المنتج الحالي ليس تطبيقًا عامًا جديدًا ولا صفحة خدمات منفصلة. لا تغيّر الغرض إلى متجر أو لوحة إدارة أو تصميم مختلف.

## 2. النطاق والمنتج الصحيح

التعديلات الخاصة بهذا المنتج تكون داخل:

`artifacts/backlink-pages-platform`

الـ artifact الصحيح هو:

`artifacts/backlink-pages-platform`

لا تعدّل تطبيقات `artifacts/sabaik-almasa` أو `artifacts/sabaik-platform` أو `artifacts/api-server` عند إضافة صفحات إلى منصة الروابط، إلا إذا طلب المستخدم ذلك صراحة. هذه التطبيقات منتجات أخرى.

## 3. الأقسام والدومينات

| القسم | الدومين الرئيسي للـ Backlinks | ملف البيانات |

| السهم | أصل البيئة الحالية وقت التوليد | `src/data/sitePages.ts` و`public/site-pages.json` |

- الواجهة والتوجيهات: `artifacts/backlink-pages-platform/src/App.tsx`

- مولد مقالات الصفحات والروابط: `artifacts/backlink-pages-platform/src/shared/pageArticle.js`

## 4. قواعد غير قابلة للتفاوض

### الهوية والتصميم

- حافظ على نفس الألوان، الخطوط، البطاقات، المسافات، اتجاه RTL، ونمط صفحات التفاصيل.
- لا تضف مكتبة تصميم جديدة ولا تعيد كتابة الواجهة من الصفر.
- لا تنشئ artifact جديدًا؛ هذا المنتج له artifact قائم.
- لا تغيّر أسماء الأقسام أو شكل التنقل إلا بطلب صريح.
- أي تحسين بصري يجب أن يكون امتدادًا مباشرًا للتصميم الحالي، لا اتجاهًا جديدًا.

### اللغة والعناوين

- كل العناوين العامة والداخلية يجب أن تكون بالعربية.
- نص الرابط الداخلي ومسار الرابط يجب أن يبنيا من **نفس عنوان الصفحة العربي**.
- لا تستخدم معرفات مثل `p-059` أو `s-001` أو `t-001` كرابط عام جديد.
- هذه المعرفات يمكن أن تبقى داخل البيانات للتنظيم الداخلي فقط.
- إذا تكرر عنوانان داخل القسم نفسه، أضف رقمًا قصيرًا للمسار فقط لمنع التعارض، مع إبقاء نص الرابط عنوانًا عربيًا واضحًا.
- لا تترك عناوين إنجليزية أو transliteration عندما يمكن إنشاء عنوان عربي مناسب.

### البطاقات والصفحات

- البطاقة تعرض الصورة والرقم الداخلي والتصنيف والعنوان والوصف، ولا تعرض مسار `/page/...` كنص.
- البطاقة تقود إلى صفحة التفاصيل ذات المسار العربي.
- صفحة التفاصيل تحتوي على:
  - عنوان الصفحة العربي.
  - سطر `مواقع صديقة` يحمل رابط الصفحة الخارجية الأصلية.
  - حقل `اقتراحاتنا` ويكون اسم الصفحة داخله رابطًا خارجيًا فعليًا.
  - صورة الصفحة.
  - مقال طويل مخصص للعنوان.
  - روابط الأقسام والشبكة الموجودة أصلًا.
- لا تحذف الروابط الخارجية الأصلية خلف الأزرار أو النصوص.

### المقالات

- كل صفحة جديدة يجب أن تحتوي على مقال عربي لا يقل عن 900 كلمة.
- المولد الحالي يضمن حدًا فعليًا لا يقل عن 980 كلمة تقريبًا لكل صفحة؛ لا تقلل هذا الحد.
- المقال يجب أن يذكر عنوان الصفحة وموضوعها وتصنيفها وسياق القسم، ولا يكون نصًا عامًا منفصلًا عن العنوان.
- لا تنسخ مقالًا يدويًا داخل كل صفحة. عدّل `src/shared/pageArticle.js` إذا كان المطلوب تغيير قالب المقال للجميع.
- يجب أن يبقى المولد نفسه مستخدمًا في الواجهة وفي تصدير Hostinger حتى لا تختلف النسختان.

### كلمات البحث والـ Backlinks

داخل كل مقال يجب وجود ثلاث كلمات بحث رئيسية مرتبطة بروابط فعلية إلى الصفحة الرئيسية للقسم:

- السهم: كلمات تنظيف عربية، والرابط إلى أصل البيئة الحالية وقت توليد البيانات.
- سبائك الماسة: كلمات تأجير حاويات ونقل مخلفات، والرابط إلى `https://sabaik.net/`.
- تقي: كلمات تأجير حاويات ونقل مخلفات، والرابط إلى `https://taqigroup.com/`.

قواعد الرابط:

- الرابط يجب أن يكون HTML فعليًا داخل المقال، وليس نص URL فقط.
- لا تثبّت نطاق السهم في المولد أو البيانات؛ استخرجه من `resolveBuildSiteOrigin()` عند التوليد، وأعد التوليد لكل بيئة.
- استخدم Anchor Text عربيًا مفهومًا ومناسبًا للبحث.
- لا تستخدم `nofollow` لهذه الروابط ما لم يطلب المستخدم ذلك.
- يجب أن تظهر الروابط في React وفي HTML المصدّر.
- لا تربط كلمات القسم بدومين قسم آخر.

## 5. طريقة إضافة صفحات جديدة

عند طلب إضافة صفحات:

1. حدد القسم الصحيح: السهم أو سبائك الماسة أو تقي.
2. لا تضع صفحات قسم داخل ملف قسم آخر.
3. استخدم مصدر الروابط الأصلي الخاص بالقسم أو المولد الموجود، ولا تكتب 100 صفحة يدويًا داخل `App.tsx`.
4. ولّد عنوانًا عربيًا لكل صفحة من نفس موضوع الرابط.
5. اربط كل صفحة بصورتها المناسبة من مكتبة الصور المحلية أو الصورة المسموح بها في المصدر.
6. اترك `App.tsx` لعرض البيانات المشتركة؛ لا تنشئ مكونًا مختلفًا لكل صفحة.
7. تأكد أن المسار الداخلي العربي مشتق من نفس العنوان.
8. تأكد أن المقال والـ Backlinks يتم توليدهما تلقائيًا للصفحة.
9. حدّث العدد الإجمالي والتصنيفات تلقائيًا من البيانات، ولا تكتب العداد يدويًا.
10. صدّر نسخة Hostinger بعد اكتمال البيانات.

## 6. أوامر التحقق والتصدير

بعد أي إضافة أو تعديل على الصفحات:

```bash
pnpm --filter @workspace/backlink-pages-platform run typecheck
node scripts/generate-backlink-platform-data.mjs
node scripts/generate-taqi-pages-data.mjs
node scripts/export-backlink-platform.mjs
```

شغّل فقط مولد البيانات الخاص بالقسم الذي تغيّر، ثم شغّل التصدير. إذا كان المصدر يحتاج إلى إعادة توليد، لا تعدّل ملفات البيانات المولدة يدويًا ثم تترك المولد يعيد حذف التعديل.

بعد التصدير تحقق من:

- نجاح TypeScript.
- نجاح Vite build.
- وجود العدد المطلوب من الصفحات.
- عدم وجود صفحة بلا عنوان عربي.
- عدم وجود مسارات عامة جديدة من نوع `p-` أو `s-` أو `t-`.
- وجود مقال لا يقل عن 900 كلمة لكل صفحة.
- وجود ثلاث روابط كلمات بحث إلى الدومين الصحيح داخل كل مقال.
- وجود HTML لكل صفحة في `backlink-pages-platform-hostinger`.
- تحديث `backlink-pages-platform-hostinger.zip`.
- إعادة تشغيل workflow ومعاينة صفحة رئيسية وصفحة تفاصيل من كل قسم.

## 7. التشغيل والمعاينة

الـ workflow الخاص بالواجهة هو:

`artifacts/backlink-pages-platform: web`

بعد تغييرات React أو CSS أو التصدير:

1. أعد تشغيل workflow.
2. افحص سجل المتصفح بحثًا عن أخطاء.
3. عاين الصفحة الرئيسية.
4. عاين صفحة تفاصيل من السهم وسبائك الماسة وتقي.
5. لا تعتبر نجاح البناء وحده كافيًا؛ يجب التأكد من العرض والروابط.

## 8. قائمة قبول الصفحة الجديدة

لا تعتبر الصفحة مكتملة إلا إذا تحققت البنود التالية:

- [ ] عنوان عربي واضح ومطابق لموضوع الرابط.
- [ ] صورة مناسبة.
- [ ] تصنيف صحيح.
- [ ] بطاقة بنفس تصميم البطاقات الحالية.
- [ ] لا يوجد مسار تقني ظاهر داخل البطاقة.
- [ ] رابط البطاقة الداخلي مبني من عنوان الصفحة العربي.
- [ ] صفحة تفاصيل تعمل عند الفتح المباشر.
- [ ] `مواقع صديقة` يحمل الرابط الخارجي الأصلي.
- [ ] `اقتراحاتنا` يحتوي اسم الصفحة كرابط خارجي فعلي.
- [ ] مقال عربي لا يقل عن 900 كلمة.
- [ ] ثلاث كلمات بحث مرتبطة بالدومين الرئيسي للقسم.
- [ ] الصفحة موجودة في حزمة Hostinger.
- [ ] لا توجد أخطاء في TypeScript أو المتصفح.

## 9. صيغة جاهزة لإعطائها لأي Agent جديد

استخدم هذه الرسالة عند بدء Agent جديد:

> اقرأ `replit.md` ثم اقرأ `docs/backlink-pages-platform.md` بالكامل قبل تعديل أي ملف. أريد إضافة [عدد] صفحات جديدة إلى قسم [السهم/سبائك الماسة/تقي]. التزم حرفيًا بنفس الهوية والتصميم والبنية والروابط والمميزات الحالية. لا تبتكر تصميمًا أو نظامًا جديدًا، ولا تعدّل التطبيقات الأخرى. لكل صفحة: استخدم عنوانًا عربيًا، اجعل المسار الداخلي مبنيًا من نفس العنوان، أضف مقالًا عربيًا لا يقل عن 900 كلمة، وأضف ثلاث كلمات بحث داخل المقال مرتبطة Backlinks بالدومين الرئيسي للقسم. حدّث البيانات والمولدات، شغّل الفحوصات، أعد تصدير `backlink-pages-platform-hostinger.zip`، ثم عاين صفحات من الأقسام المتأثرة.

إذا أردت منع أي تغيير خارج نطاق إضافة الصفحات، أضف:

> لا تغيّر الألوان أو التخطيط أو أسماء الأقسام أو سلوك الروابط الموجودة. إذا وجدت تعارضًا أو نقصًا في المصدر، توقف واسأل قبل ابتكار حل جديد.

## 10. قاعدة عند وجود غموض

إذا لم يحدد المستخدم القسم أو الدومين أو مصدر الروابط أو صور الصفحات، لا تفترض. اسأل سؤالًا واحدًا مركزًا قبل إنشاء الصفحات. أما إذا كانت كل المعلومات موجودة، نفّذ مباشرة وفق هذا الملف ولا تطلب موافقة على التفاصيل التي يحددها التوثيق.
