# توثيق بوابة SEO والإصلاح من لوحة الإدارة

**آخر تحديث:** 19 أكتوبر 2026  
**الحالة:** اكتمل البناء والتحقق المحلي للحزمتين؛ لم يُنشر أي تغيير ولم تُفحص حالة الإنتاج الحية.

## الهدف المعتمد

إضافة مسار عمل من قسم SEO يسمح للمستخدم المخوّل أن:

1. يشغّل فحصاً كاملاً لروابط sitemap ولكل ملفات HTML المنشورة.
2. يرى نتيجة كل صفحة، درجة Rank Math، ونوع كل مشكلة أو تحذير.
3. يطلب إصلاحاً بالذكاء الاصطناعي للصفحات التي يمكن تعديلها بأمان، أو يعدّل الحقول يدوياً.
4. يحفظ التعديلات في قاعدة البيانات بحيث تبقى بعد إعادة بناء الحزمة.
5. يعيد بناء sitemap، ويتحقق من وجود الصفحة فيها عندما تسمح سياسة الفهرسة، ثم يعيد الفحص.

## قرارات أكدها المستخدم

- يجب أن تكون صفحات المناطق والصفحات الثابتة قابلة للتحرير الدائم بالذكاء الاصطناعي، مع إتاحة التعديل اليدوي أيضاً.
- مصدر قاعدة البيانات والوسائط للحزمتين الكاملتين في هذا الإصدار هو بيانات المشروع الحالية: `data/sabaik.db` والوسائط التي يشير إليها.
- هذا الإذن خاص بهذا الإصدار. فك الحزمة الكاملة على موقع قائم يستبدل قاعدة البيانات والملفات المرفوعة؛ لا يعني ذلك إذناً بنشرها أو استبدال بيانات الإنتاج.

## ما تحقق قبل بدء هذه المرحلة

- فحص بوابة Rank Math على مرحلتي PHP وNode الموجودتين أعاد 489/489 صفحة بدرجة 100/100 لكل منهما، وHTML المرحلتين متطابق.
- هذا الفحص يخص المخرجات المرحلية الموجودة، وليس قاعدة Hostinger الحية أو أحدث نسخة من `data/sabaik.db`. قاعدة المصدر أحدث من قواعد المرحلتين، ولم تُقرأ قاعدة الإنتاج الحية.
- ملف الملاحظات التاريخي `seo-rank-math-gate-implementation-notes.md` ما زال يعرض نتيجة قديمة (396/489)؛ يلزم تحديثه بعد بناء وفحص الحزم الجديدة.
- لوحة SEO الحالية تعرض تدقيق sitemap وفهرس HTML وأنواع الفحوص، وتتيح إصلاح بعض سجلات CMS.
- صفحات المناطق وبعض الصفحات الثابتة ليس لها سجل محتوى قابل للتحرير في CMS الحالي.
- `/call-now` صفحة قابلة للفهرسة؛ وهي موجودة الآن في قائمتي الصفحات الثابتة في مولدي sitemap لـNode وPHP.

## استنتاجات الاستمرار في 19 أكتوبر 2026

- المساعد المشترك لتنقية قيم override وتطبيق العنوان والوصف وعبارة التركيز وH1 والمحتوى موجود، وله اختبار TypeScript أساسي. لم يكن اختبار PHP لمساعده مضافاً إلى أوامر `scripts/package.json`.
- مسارات القراءة والحفظ في Node وPHP موجودة؛ الحفظ يحدّث ملف HTML المنشور ثم يسجل القيمة في `site_settings`، مع محاولة استرجاع HTML إذا فشل حفظ قاعدة البيانات. يلزم اختبار ذلك في PHP فعلياً.
- الواجهة تحتوي محرر override يدوياً، وتستدعي عند الحفظ دورة تحديث sitemap ثم إعادة التدقيق. كما تستدعي `/api/admin/ai/fix-static-seo-check` لإصلاح الصفحات الثابتة، لكن هذا المسار غير موجود في خادم Node أو قائمة مسارات الذكاء الاصطناعي في PHP؛ لذلك زر AI غير مكتمل حتى إضافة الخادمين.
- لا يستدعي بناء Hostinger حالياً `applySeoPageOverrideToHtml` ولا نظيره PHP بعد prerender. لذلك قد تُفقد تغييرات HTML عند إعادة البناء حتى لو بقيت في قاعدة البيانات؛ يجب تطبيق القيم المحفوظة بعد prerender وقبل نسخ المخرجات إلى الحزمتين.
- جرد `dist/public` الحالي يؤكد وجود صفحات HTML مستقلة للمناطق ولصفحات `/about` و`/services` و`/cleaning-packages` و`/contact/شركة-تنظيف-بالرياض` و`/faq/تنظيف-المنازل-بالرياض` و`/terms` و`/privacy` و`/blog` و`/call-now`. لا توجد حالياً ملفات HTML مستقلة للمسارات `/offers` و`/partners` و`/why-us/*`؛ يجب ألا يُسمح لمسار HTML override لهذه الروابط قبل توليد HTML مستقل لها.
- لم يُبنَ في هذه المرحلة أي ZIP جديد، ولم تُقرأ قاعدة Hostinger الحية أو تُحدّث. نتيجة 489 صفحة الواردة أعلاه تخص مخرجات مرحلية أقدم من هذا الاستمرار.

**قرارات الاستمرار وسببها:** سأحافظ على المسارات وcanonical وrobots كما هي، وأبقي حفظ بيانات override في `site_settings` من دون تعديل schema. سأجعل ملف HTML المحفوظ المصدر الذي يعاد تطبيق override عليه في بناء PHP وNode، وأضيف اختبارات PHP موازية لمساعد TypeScript، وأكمل مسار AI في الخادمين بحيث لا يعيد اقتراحاً إلا بعد فحص Rank Math للنتيجة. سأطابق قائمة المسارات القابلة للتحرير مع HTML المستقل المتولد فعلياً بدلاً من نجاح حفظ قاعدة البيانات وحده.

## التنفيذ والتحقق المرحلي

- حُصرت المسارات القابلة للتحرير على صفحات HTML المستقلة التي يولدها البناء حالياً، مع إبقاء جميع صفحات `/areas/[slug]`؛ استُبعدت المسارات SPA-only التي لا تملك ملف HTML منفصلاً.
- أضيف اختبار PHP موازٍ لاختبار TypeScript، واختبار تكاملي بمجلد وقاعدة مؤقتين يثبت أن بناء HTML يعيد تطبيق override المحفوظ بأمان، ويحافظ على canonical، ويتجاهل المسارات غير المسموح بها.
- أضيفت خطوة البناء بعد prerender وقبل تجميع الحزمتين لتطبيق قيم `site_settings` على HTML الجديد. قاعدة المصدر الحالية لا تحتوي على overrides، ومفتاح الترحيل الأحادي المرة مسجل كمكتمل؛ تشغيل خطوة التطبيق الحالية لم يغيّر HTML وطبّق صفراً من القيم.
- أضيف مسار إصلاح الصفحات الثابتة في API Node وPHP. يطلب الحقول المطلوبة، ثم يمرر الصفحة كاملة إلى محلل Rank Math، ولا يعيد الاقتراح للحفظ إذا بقي مانع نشر أو لم يجتز الفحص المطلوب. لم يُختبر الاستدعاء الحي لمزود AI بعد؛ الاختبارات الحالية لا تستخدم اتصالاً خارجياً.
- بعد إعادة تشغيل API، أعاد طلب POST غير موثّق إلى مسار إصلاح AI الرمز `401 Unauthorized` المتوقع؛ هذا يثبت أن المسار محمي، ولا يثبت سلوك إصلاح موثّق أو استدعاء مزود AI.
- رُبط المحرر اليدوي بإجراء الحفظ فعلياً، وصار الإجراء يفحص وجود عنوان الصفحة في sitemap المبني قبل إعادة التدقيق؛ صفحات noindex أو canonical غير الذاتي تبقى خارج sitemap كما هي.
- أضيف ملخص منفصل لعدد الصفحات بنتيجة 100/100 وعدد الصفحات التي بها تحذيرات أو مشكلات، مع الحفاظ على أعداد عناصر الفحص وأنواع التعثر الحالية.
- نجاح `pnpm run typecheck` بعد إعادة بناء اعتماديات المكتبة المشتركة. كما نجحت اختبارات تطابق مدخلات Rank Math وأهداف إصلاحه ومطابقة المسارات وقوة الكلمات وتخزين التدقيق وروابطه، واختبارا overrides في TypeScript وPHP واختبار إعادة تطبيق HTML واختبار محاولات إصلاح Hostinger؛ واجتازت ملفات PHP فحص الصياغة.
- قبل الحزمة النهائية، فُحصت قاعدة المصدر للقراءة فقط: لا توجد overrides محفوظة حالياً، وترحيل metadata معلّم كمكتمل. جميع مصادر الروابط القديمة التي قد يوقفها نص البناء متوقفة بالفعل (أو معلمة صراحةً للاحتفاظ بها)، لذا لا يغير بناء الحزمة حالياً حالة صفحة مصدر نشطة. أُخذت أيضاً نسخة SQLite احتياطية مؤقتة خارج مساحة العمل قبل البناء.
- توقفت المحاولة الأولى للبناء عند مقارنة نصية بين مسارات عربية حرفية ومشفرة. عُدّلت المقارنة لتطبيع المسار فقط عند مقارنة مجموعتي URLs، مع إبقاء sitemap الصادر دون إعادة كتابة، والحفاظ على فحص كل ملف sitemap، ورفض أي رابط مكرر بعد فك الترميز أو أي اختلاف حقيقي في المسار أو الأصل.
- نجح اختبار التطبيع، ثم اجتاز البناء النهائي بوابة Rank Math في حزمتَي PHP وNode: `489/489` صفحة لكل حزمة بدرجة `100/100`، وHTML متطابق بايتياً عبر 489 ملفاً. احتوت كل sitemap على 482 رابطاً، وتكافأت المجموعتان بعد فك ترميز المسار. ظهر `/call-now` في كلتيهما.
- أظهر الفحص أيضاً سبعة تحذيرات CTA وثلاثة أمثلة ضمن مجموعة عنوان مكرر واحدة بين صفحات sitemap القابلة للفهرسة. هذه تحذيرات الجودة الظاهرة في سجل البناء، وليست سبب توقفه؛ لا تُعدّ محسومة في هذا الإصلاح.
- اكتمل التحقق من الأرشيفين: نجح `zip -T` لكليهما؛ وفحص `PRAGMA integrity_check` أعاد `ok` لقواعد SQLite داخل أرشيف PHP وNode. احتُفظ بمفتاح PHP السابق. ملفات البناء موجودة تحت `generated-artifacts/php/cleanflow-services-hostinger.zip` (نحو 59,485 KB) و`generated-artifacts/node/cleanflow-services-node.zip` (نحو 62,075 KB).
- اختلفت بيانات التحليلات أثناء تشغيل المعاينة: نسخة ما قبل البناء فيها 3,446 مشاهدة و108 زوار نشطين؛ قاعدة كل حزمة فيها 3,450 مشاهدة و108 زوار؛ والمصدر الحالي بعد المعاينة فيه 3,454 مشاهدة و109 زوار. مقارنة الصفوف المنطقية أكدت أن التغييرات محصورة في جدولي `active_visitors` و`page_views`، ومخطط بقية البيانات وصفوفها لم يتغير. لا تُستعد النسخة الأقدم ولا تُستبدل بها الحزم؛ فالفرق أحداث زيارات لاحقة لوقت اللقطة.

**ما لم يُثبت بعد:** لم يُختبر مسار AI باستدعاء حي لمزود، ولم تُختبر لوحة الإدارة بعد تسجيل الدخول. كما لم تُرفع الحزم إلى Hostinger ولم تُفحص sitemap أو الصفحات الحية. نجاح البناء المحلي لا يثبت نشر الإنتاج أو سلامته.

أُعيد تشغيل خدمتي API والويب بعد التغييرات، وظهرتا بحالة تشغيل؛ حمّلت الصفحة الرئيسية العامة وواجهات API العامة بنجاح. لا تمثل هذه المعاينة اختباراً للوحة الإدارة المسجّلة الدخول.

## استنتاجات التنفيذ

- التعديل على سجلات CMS وحدها لا يكفي للصفحات الثابتة؛ ملفات HTML المنشورة تُخدم مباشرة، كما أن React يمسح محتوى prerender عند بدء التطبيق. لذلك يحتاج التحرير الثابت إلى سجل دائم، وتحديث HTML المنشور، وإعادة تطبيق القيم بعد تحميل React.
- لن تتغير المسارات أو canonical أو robots تلقائياً. إضافة URL إلى sitemap مشروطة بأن تكون الصفحة قابلة للفهرسة وذات canonical ذاتي؛ صفحات `noindex` تبقى خارج الخريطة.
- الصفحات المدارة حالياً من سجلات المقالات/صفحات SEO/الخدمات/الباقات يجب أن تستمر باستخدام محرراتها الحالية. مسار override الجديد مخصص للصفحات الثابتة وصفحات المناطق، مع قائمة مسارات مسموح بها لمنع تعديل ملفات عشوائية.
- يجب أن تطبق الحزمة الكاملة overrides المخزنة في قاعدة البيانات على HTML بعد التوليد وقبل فحص البوابة، وأن تستخدم PHP وNode المخرجات نفسها.
