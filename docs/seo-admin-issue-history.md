# سجل أعمال لوحة SEO ومشكلات الإصلاح

**آخر تحديث أولي:** 18 أكتوبر 2026  
**النطاق:** منصة CleanFlow Services، لوحة SEO، ونسخة Hostinger PHP.

## الأعمال السابقة

- جرى توحيد سياسة تحليل Rank Math الداخلية بين محرر المقالات وتدقيق الموقع، مع إبقاء تقييم HTML المنشور منفصلاً عن بيانات السجل المحفوظة.
- بُنيت حزمة Hostinger PHP كاملة بعد طلب سابق، وتشمل كود الواجهة وPHP وقاعدة SQLite وملفات الرفع.
- اجتازت الحزمة المحلية فحص ZIP، وفحص سلامة SQLite، وفحص صياغة ملفات PHP. كما أعادت دالة خريطة الكلمات 50 نتيجة على قاعدة مساحة العمل، وحُفظ مفتاح التوقيع السابق.
- لم يكن هناك تأكيد بأن الحزمة رُفعت إلى Hostinger أو أن الخطأ اختفى على الموقع الحي؛ نجاح الاختبارات المحلية لا يثبت نجاح نقطة النهاية على الإنتاج.

## الأدلة الجديدة

الملف المرفق بتاريخ 18 أكتوبر 2026 يسجل مشكلتين منفصلتين:

1. `GET /api/admin/ai/keyword-map` يعيد `503 Service Unavailable`؛ لذلك لم تُحمّل خريطة الاستهداف.
2. `POST /api/admin/ai/fix-seo-check` يعيد `422 Unprocessable Content`. رسالة الخادم تقول إن الإصلاح لم يُحفظ بعد محاولتين، مع بقاء فحص عبارة التركيز في العنوان وعمق محتوى يبلغ نحو 262 كلمة مقابل حد 300 ودرجة 74/80.

ويظهر أيضاً تحذير إهمال `XSLTProcessor` ورسالة `Target website not loaded`. لا يثبت الملف وحده أن هذين التحذيرين هما سبب فشل نقطتي API أعلاه.

## الحالة عند بدء التحقيق الجديد

- خريطة الاستهداف: ما زال سبب استثناء PHP على الإنتاج غير مثبت من سجل المتصفح وحده؛ يجب تتبع مسار PHP وقاعدة البيانات، وعدم اعتبار نجاح اختبار قاعدة مساحة العمل دليلاً على سلامة الإنتاج.
- إصلاحات الذكاء الاصطناعي: الواجهة تطلب إصلاح فحص واحد، بينما الخادم يقيّم الصفحة الناتجة كاملة وفق بوابة النشر. يجب أن تبقى البوابة موحدة، مع جعل سير الإصلاح قابلاً لإزالة جميع موانع النشر قبل الحفظ بدلاً من رفض إصلاح جزئي لا يستطيع المستخدم تطبيقه.
- لا تُعدّ أي من المشكلتين محلولة على الإنتاج حتى يُختبر السلوك بعد النشر.
