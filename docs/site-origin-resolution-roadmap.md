# أصل الموقع حسب بيئة التشغيل والبناء

## الطلب

كل رابط ذاتي يُنشأ للموقع يجب أن يستخدم أصل البيئة الحالية بلا استثناء: Replit، أو localhost، أو نطاق البناء/الاستضافة. يشمل ذلك HTML وcanonical وOpen Graph وJSON-LD وsitemap وrobots وllms.txt وروابط الصور الذاتية. عند نقل حزمة مبنية، يجب أن يعيد المضيف الذي يقدمها ربط هذه الروابط بأصل الطلب. تبقى الروابط المقصودة لخدمات وأطراف خارجية كما هي.

## التنفيذ المعتمد

- أولوية محلل البناء: `CLEANFLOW_SITE_ORIGIN` الصالح، ثم نطاق Replit النشط، ثم `VITE_PUBLIC_SITE_URL`، ثم localhost مع منفذ البناء. لا يوجد نطاق إنتاج افتراضي.
- Vite يعيد ربط HTML وملفات sitemap/robots/llms.txt بأصل الطلب في dev وpreview؛ طلبات وحدات Vite والملفات الثابتة لا تُعامل كصفحات HTML.
- مولّد sitemap يعيد كتابة الأصول الذاتية المعروفة، بما فيها أصل `site_public_url` المخزن، ويترك نطاقات الأطراف الخارجية دون تغيير. يسمح مدقق sitemap بـHTTP/HTTPS والمنافذ المحلية فقط عند مطابقة أصل البيئة المتوقع.
- Node وPHP يستخدمان أصل الطلب في المسارات الديناميكية. إنشاء حزم Hostinger يرمّز أصل البناء والأصول القديمة المحفوظة داخل HTML/XML/TXT، ثم يستبدل PHP الرمز بأصل الطلب؛ خطوة بناء الحزمة لا تعدّل قاعدة البيانات. بعد رفع الحزمة، يحفظ إجراء الإدارة «بناء وحفظ خريطة الموقع» أصل طلب الإنتاج المعتمد مباشرةً داخل sitemap.xml والملفات الفرعية؛ يظل ترميز الأصل مقتصراً على مخرجات البناء القابلة للنقل. تحفظ صفحة الإعدادات أصل الموقع الحالي وقائمة aliases عند تأكيد مسؤول الموقع ذلك.
- أصبحت صفحة الإعدادات تحفظ النطاق العام الحالي بعد فتحها من النطاق النهائي فقط؛ ترفض localhost ومعاينات Replit والنطاق المختلف. يظل أصل طلب التشغيل مرجع HTML وcanonical وsitemap والفحص، أما القيمة المحفوظة فتخدم أدوات البناء وإعادة الربط.
- عند تغيير `site_public_url` تحفظ القيمة السابقة في قائمة aliases محدودة، ويستخدمها مولّد sitemap وبناء Hostinger وNode لإعادة كتابة الروابط الذاتية القديمة إلى الأصل الحالي دون تعديل السجلات التاريخية.
- مولّد بيانات منصة الروابط الخلفية يفضّل `CLEANFLOW_SITE_ORIGIN`/`VITE_PUBLIC_SITE_URL` الصريحين، ثم النطاق المحفوظ، ثم أصل البناء المحلي. يعيد `prebuild` توليد روابط الصفحات من sitemap قبل بناء المنصة، وروابط المقالات تستمد أصلها من URL الصفحة بدلاً من نطاق ثابت.
- canonical في PHP وNode يُقارن بأصل البيئة المتوقع، بما في ذلك البروتوكول والمنفذ والمسار. أزيل اعتماد واجهة Rank Math على نطاق إنتاج ثابت؛ تحليل المسار لا يحتاج إلى أصل موقع.
- دليل Hostinger والذاكرة موحّدان مع هذا السلوك. هذا الملف هو خارطة الطريق الوحيدة لهذا الموضوع؛ أُزيلت ملفات التسليم وموضوعات الذاكرة القديمة أو المكررة.

## التحقق المنجز

- اختبارات أصل البناء: 8 ناجحة؛ اختبارات sitemap: 3 ناجحة؛ اختبار تكافؤ Rank Math ناجح.
- اختبارات PHP نجحت لمسارات canonical المحلي مع المنفذ، وSEO page overrides، وHostinger SEO retry.
- فحوص TypeScript نجحت للمكتبات وscripts وAPI وواجهة CleanFlow.
- شُغّل مولّد sitemap فعلياً مع `http://localhost:4321`، ونطاق اختبار `https://aiservx.example`، ونطاق Replit النشط. نجح التحقق لكل منها (508 عنوان صفحة و481 صورة)، ثم تُرك sitemap المصدر مولداً على أصل Replit الحالي.
- طلب معاينة Replit أعاد canonical وOpen Graph وsitemap وrobots على أصل المعاينة، دون أصل alsahmm القديم؛ عادت صفحة الموقع للعمل بعد ضمان عدم اعتراض ملفات Vite الداخلية.
- في 2026-10-21 بُني أرشيف PHP كامل بعد تشغيل بوابة SEO قبل ترميز الأصول؛ اجتازت الصفحات الـ515 بوابة Rank Math بدرجة 100/100.
- اختُبر ZIP المستخرج عبر PHP مع Host تجريبي وHTTPS ومنفذ 8443: canonical وOpen Graph وJSON-LD للصفحة الرئيسية وCleanFlow Platform، وروابط sitemap (مؤشر و500 صفحة)، وrobots أعادت أصل الطلب دون الرمز أو الأصل القديم. نجح `PRAGMA integrity_check`، واحتوى الأرشيف 22 ملف رفع؛ حجم ZIP 62,913,028 بايت.
- أضيف زر في إعدادات الموقع لحفظ أصل النطاق الجاري؛ تُحفظ الأصول السابقة كقائمة إعادة كتابة، ولا يُسمح بحفظ عنوان معاينة. اختبارات أصل البناء وإعادة ربط الروابط ومصدر النطاق المحفوظ واختبارات رابط مقالات المنصة ناجحة.
- في 2026-10-22 تحققت حزمة PHP المنفصلة `cleanflow-services-aiservx.com.zip`: اختبار الأرشيف سليم، وفحص Runtime وجد `sitemap.xml` وملفيه الفرعيين. محاكاة HTTPS على `aiservx.com` أعادت مؤشرًا صالحًا، كما أعاد `/api/sitemap/generate` الأصل `https://aiservx.com` و508 رابطًا؛ لم يظهر رمز الأصل المؤقت أو `alsahmm.com`.

## حدود التحقق

لم يُرفع الأرشيف إلى Hostinger بعد؛ اختبار Host كان محاكاة محلية ولا يثبت DNS أو TLS أو إعدادات Apache على الاستضافة الحية. نطاق aiservx أعلاه كان محاكاة إعداد بناء فقط. لا تدّعِ تحققاً إنتاجياً دون اختبار المضيف المنشور.

اختبار حزمة `aiservx.com` في 2026-10-22 محلي كذلك؛ نجاحه يؤكد سلوك الحزمة عند تمرير طلب HTTPS بهذا المضيف، ولا يؤكد رفعها أو إعدادات النطاق الحية.

## الاستكمال دون إعادة تحليل

لا تبدأ مسحاً عاماً جديداً. عند استئناف هذا الموضوع، استخدم هذه الصفحة وموضوع الذاكرة الوحيد `site-origin-policy.md`، ثم اختبر فقط أصل البيئة الذي لم يُختبر أو التغيير الذي طرأ. لا تُنشئ ملف تسليم موازياً ولا تُعد فحص النظام كله.
